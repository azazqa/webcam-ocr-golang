# 개발 계획 재검토

- 대상: 「Capture 핵심 구현」 개발 계획 (PLAN_REVIEW 반영본)
- 작성일: 2026-11-19

---

## 1. 새로 정해야 할 점

| # | 위치 | 내용 | 제안 | 정할 시점 |
|---|---|---|---|---|
| 1 | 수신·감지 루프 사이의 최신 1칸 | 감지가 수신보다 빠르면 같은 프레임을 여러 번 처리할 수 있음. 그러면 `MinStableFrames`가 중복 프레임으로 채워져 안정 판정이 틀어짐. | 칸에 `{프레임, 수신 시각, 일련번호}`를 함께 넣고, 감지 루프는 새 일련번호가 들어올 때만 처리. 프레임 시각은 감지 시각이 아니라 수신 시각(`Run` 시작 기준, 단조 시계) 사용. | 구현 전 |
| 2 | 무변화 판정, 카메라 멈춤 | ① 무변화 판정을 프레임이 들어올 때만 하면, 카메라가 멈췄을 때 자동 종료가 영원히 안 됨.<br>② `camera.Grab()`은 프레임을 기다리는 동안 잠금을 잡고 있어, 카메라가 멈추면 수신 루프가 끝나지 않음. 그 상태에서 호출하는 쪽이 `Close()`를 부르면 같이 멈춤. | ① 감지 루프에 타이머를 두어 프레임이 없어도 무변화 시간을 확인.<br>② `Run`은 수신 루프 종료를 정해진 시간(예: 2초)까지만 기다리고 반환. 카메라를 닫는 것은 호출하는 쪽 책임으로 명시(`capture`는 닫지 않음). | 구현 전 |
| 3 | 종료 사유 | `ctx`가 취소됐을 때 종료 사유가 정해져 있지 않음. 카메라 연결이 끊기는 등 `Grab` 오류가 계속될 때의 처리도 없음. | `ctx` 취소는 `StopByUser`로 처리하거나 `StopByCancel` 추가. `Grab`이 연속 N회(예: 10회) 실패하면 `StopByError`로 종료. | 구현 전 |
| 4 | `ManualCapture` | "추출 중이 아니면 오류"인데, 아직 프레임이 하나도 없을 때의 처리가 빠져 있음. | 아직 프레임이 없으면 오류 반환. 수동 저장도 `Count`에 포함한다고 명시. | 구현 중 |
| 5 | `Start` | `Start`에서 세션 폴더와 session.json을 만들기 때문에, 그 뒤 `Run`을 실행하지 않으면 빈 세션 폴더가 남음. | 폴더 생성을 `Run` 시작 시점으로 미루거나, `Start` 다음 바로 `Run`을 호출하도록 사용 규칙을 정함. | 구현 중 |
| 6 | 저장 대기열 | 저장 고루틴 버퍼 크기와, 버퍼가 가득 찼을 때 감지 루프가 기다리는지 여부가 정해져 있지 않음. | 버퍼 8칸, 가득 차면 기다림. 저장은 2~5초에 한 번꼴이라 실제로 찰 일은 거의 없음. 이미지 1장 약 8MB(1080p RGBA) → 메모리 최대 64MB 수준. | 구현 중 |
| 7 | JSON의 시간 값 | `time.Duration`을 그대로 JSON으로 저장하면 나노초 정수(`180000000000`)가 됨. config의 `IdleTimeout`과 session.json의 감지 기준값이 해당. | `"3m"`, `"300ms"` 같은 문자열이나 초 단위 숫자로 저장. | 구현 중 |
| 8 | CSV 열 | 수동 저장 줄의 "변화율" 칸 값과 "촬영시각" 형식이 정해져 있지 않음. | 수동은 마지막 저장 화면과의 차이를 계산해 넣거나 빈칸으로 둠. 촬영시각은 `2026-11-19 14:35:12.345` 형식(로컬 시각). | 구현 중 |

## 2. 반영 확인

| 검토 항목 | 반영 | 반영 내용 |
|---|---|---|
| 1-1 수동 캡처 동시 실행 충돌 | ✅ | `ManualCapture()` 인자 없이 채널로 요청 |
| 1-2 Linux 테스트 불가 | ✅ | `FrameSource` 인터페이스 |
| 1-3 종료 방식·완료 보장 | ✅ | `Result`/`StopReason`, 저장 완료 후 반환, `ctx`는 `Run`에서만 받음 |
| 1-4 CLI 불일치, scenetest 컴파일 오류 | ✅ | CLI 복사 안 함, scenetest 옵션을 시간 단위로 |
| 1-5 최신 프레임 처리 구조 | ✅ | 수신 루프와 최신 1칸 구조, `GrabRaw`는 다음 범위로 |
| 2-1 extract | ✅ | `StableDuration`, `MinStableFrames`, 0.2초 전 프레임 선택 규칙, `MarkSaved`, 샘플 재확인 |
| 2-2 capture | ✅ | `Options` 정리, ROI 한 곳으로, 순번 위치, CSV BOM, session.json 종료 갱신, `Stats`, 60분 초과 파일 이름, 남은 공간은 다음 단계로 |
| 2-3 config | ✅ | `UserConfigDir`, 자동 종료 켜짐 여부와 시간 값 따로 저장 |
| 2-4 검증 | ✅ | `-race`, `go mod tidy`, 설계 문서 갱신 |
